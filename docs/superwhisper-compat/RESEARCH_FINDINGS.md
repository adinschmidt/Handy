# Superwhisper API request and replay findings

Date investigated: 2026-07-27  
App inspected: Superwhisper 2.16.6 (`com.superduper.superwhisper`)  
Platform: macOS  
Primary goal: document transcription and adjacent requests well enough to reproduce them without modifying system networking or installing a trusted interception certificate.

## Executive summary

Superwhisper uses several different request families:

1. **Superwhisper-proxied APIs** at `https://api.superwhisper.com`, including ElevenLabs batch transcription, cloud language models, license operations, and file sync.
2. **Regional Superwhisper inference** at `https://ai.superwhisper.com` and `https://us.ai.superwhisper.com`, using a short-lived bearer JWT.
3. **Direct provider APIs** for Deepgram, ElevenLabs realtime, OpenAI, Groq, and Anthropic. These use provider tokens or temporary provider tokens issued through Superwhisper.
4. **Model downloads and local inference**, which do not send recordings to an inference API once the local model is installed.

The most important replay result is the batch request used by the current Default mode:

```text
POST https://api.superwhisper.com/elevenlabs/v1/transcribe
Content-Type: multipart/form-data

file=@audio.ogg; type=audio/ogg; filename=audio.ogg
language_code=en
keyterms[]=...       # repeatable and optional
diarize=true|false   # supported; omitted in the observed request
```

It authenticates with:

```text
X-ID: <36-character device identifier>
X-License: <36-character license/user identifier>
X-Signature: <64 lowercase hexadecimal characters>
X-Platform: macos
```

The same `X-ID`, `X-License`, and `X-Signature` values appeared on three different cached requests: ElevenLabs transcription, cloud-model discovery, and cloud chat. The signature therefore did **not** vary with the path or request body in the observed sample. Its derivation remains unknown, but an already-authorized current set should be reusable while the device/license state remains valid.

No real IDs, license values, bearer tokens, signatures, transcripts, prompts, or synchronized files are included in this report.

## Evidence labels

- **Live-observed**: generated by operating the installed app and observing its connection.
- **Cache-confirmed**: reconstructed from macOS `CFURLCache` request and response objects created by the app.
- **Binary-confirmed**: exact strings, request fields, or code paths present in the installed app executable.
- **Inferred**: strongly suggested by the app and provider protocol, but not captured as a complete request.

## Capture approach and laptop safety

- A controlled recording was made in the app to trigger transcription.
- Network metadata was observed without decrypting TLS.
- Exact HTTP methods, URLs, headers, multipart part names, JSON keys, response status codes, and response schemas were recovered read-only from:

  ```text
  /Users/adin/Library/Caches/com.superduper.superwhisper/Cache.db
  /Users/adin/Library/Caches/com.superduper.superwhisper/fsCachedData/
  ```

- The installed Mach-O binary was inspected read-only for uncached endpoints and protocol fields.
- No interception CA was installed or trusted.
- No persistent proxy was enabled. `scutil --proxy` returned an empty dictionary after the investigation.
- Temporary analysis files were kept under `/private/tmp`.

This avoided changing system trust, global proxy settings, the app bundle, or the app’s permanent configuration.

## Live transport findings

The controlled transcription used a persistent TCP/IPv6 connection to:

```text
2606:4700:60:0:8182:72f0:2a59:afb4:443
```

DNS associated that address with `api.superwhisper.com` through Cloudflare. The observed request burst was approximately 15.1 KB sent and 1.1 KB received. The source AIFF was about 276 KB, confirming that Superwhisper compressed it before upload. A later cache-confirmed request contained Ogg pages and an `OpusHead`, so the uploaded `audio.ogg` is Ogg Opus.

The connection used TLS over TCP/443, not QUIC. Connection reuse is consistent with HTTP/2, although ALPN was not decrypted in the packet observation.

## Authentication families

### 1. Device/license headers

Used on cache-confirmed requests to:

- `/elevenlabs/v1/transcribe`
- `/models/language/cloud`
- `/v1/chat/completions`

Headers:

```text
X-ID: <UUID, 36 characters>
X-License: <UUID, 36 characters>
X-Signature: <64-character lowercase hex value>
X-Platform: macos
Accept: */*
```

Findings:

- `X-ID` was identical across all three requests.
- `X-License` was identical across all three requests.
- `X-Signature` was identical across all three requests despite different paths and bodies.
- The signature is therefore not a simple per-body digest in this sample.
- The app imports CryptoKit SHA-256, HMAC, HKDF, and AES-GCM, but those primitives are also used for file-sync encryption. Static inspection did not establish the signature algorithm.
- One hundred basic SHA-256/HMAC combinations of the observed identifiers and nearby embedded constants did not match it.

### 2. License bearer token

A 43-character bearer value was cache-confirmed on:

- `POST /license/validate`
- `POST /file/upload`
- `GET /file/check-updates?since=...`

The same bearer value was used for those requests. It is separate from the device/license header family and should not be confused with the inference JWT.

### 3. Regional inference bearer JWT

`POST https://ai.superwhisper.com/v1/c/run` used:

```text
Authorization: Bearer <JWT>
```

The captured token was a three-segment JWT with `alg` and `typ` header keys and `projectId`, `name`, `description`, and `exp` claims. It had an expiry claim and must be refreshed through the inference-key endpoints when expired.

### 4. Provider credentials

- Deepgram batch/realtime: `Authorization: Token <deepgram-token>`.
- ElevenLabs realtime: temporary `token` session parameter.
- OpenAI and Groq: bearer API key.
- Anthropic: `x-api-key` plus `anthropic-version: 2023-06-01`.
- Superwhisper’s built-in provider modes obtain temporary provider credentials from Superwhisper; user-configured “bring your own key” models connect directly to the provider.

## Replay: ElevenLabs batch transcription through Superwhisper

### Cache-confirmed request

```http
POST /elevenlabs/v1/transcribe HTTP/2
Host: api.superwhisper.com
Accept: */*
X-ID: <device-id>
X-License: <license-id>
X-Platform: macos
X-Signature: <signature>
Content-Type: multipart/form-data; boundary=<generated>
```

Observed multipart parts:

| Part | Filename | Type | Observed size |
|---|---|---|---:|
| `file` | `audio.ogg` | `audio/ogg` | 26,397 bytes |
| `language_code` | none | text | 2 bytes |
| `keyterms[]` | none | text | 12 bytes |

The complete captured multipart body was 26,782 bytes. The binary also supports repeated `keyterms[]` parts and an optional `diarize` part. The observed request omitted `diarize`.

The literal multipart part name was **`file`**, not `audio`.

### Prepare compatible audio

The app’s upload was Ogg Opus. A compatible conversion is:

```bash
ffmpeg -i input.wav -ar 16000 -ac 1 -c:a libopus -b:a 32k audio.ogg
```

The API may accept other Ogg Opus sample rates, but mono 16 kHz is a conservative replay format.

### Curl template

Set the four credential variables from a currently authorized request. Do not paste them into the script or commit them to a repository.

```bash
export SW_X_ID='<current device UUID>'
export SW_X_LICENSE='<current license UUID>'
export SW_X_SIGNATURE='<current 64-character signature>'
export SW_LANGUAGE_CODE='en'
```

Then:

```bash
curl --http2 --fail-with-body \
  --compressed \
  --request POST \
  'https://api.superwhisper.com/elevenlabs/v1/transcribe' \
  --header 'Accept: */*' \
  --header 'Accept-Encoding: gzip, deflate' \
  --header 'Accept-Language: en-CA,en-US;q=0.9,en;q=0.8' \
  --header 'User-Agent: superwhisper/2.16.6 (com.superduper.superwhisper; build:2.16.6; macOS 26.5.2) Alamofire/5.8.0' \
  --header "X-ID: ${SW_X_ID}" \
  --header "X-License: ${SW_X_LICENSE}" \
  --header 'X-Platform: macos' \
  --header "X-Signature: ${SW_X_SIGNATURE}" \
  --form 'file=@audio.ogg;type=audio/ogg;filename=audio.ogg' \
  --form "language_code=${SW_LANGUAGE_CODE}" \
  --form 'keyterms[]=Superwhisper'
```

The app’s exact cached `Accept-Encoding` value is `gzip, deflate, br`. The Apple curl installed on this laptop only decodes gzip and deflate, so the runnable template advertises those two encodings. This does not change the API semantics. With a Brotli-enabled curl, use the app’s exact value:

```bash
--header 'Accept-Encoding: gzip, deflate, br'
```

Curl generates the request-specific `Host`, `Content-Length`, and multipart `Content-Type`/boundary headers. Do not copy the old content length or boundary from a cached request.

For speaker separation, add:

```bash
--form 'diarize=true'
```

For no key terms, omit all `keyterms[]` parts.

## Realtime transcription protocols

### Deepgram WebSocket

Endpoint:

```text
wss://api.deepgram.com/v1/listen
```

Binary-confirmed configuration fields:

```text
encoding=linear16
sample_rate=16000
channels=<count>
smart_format=true
interim_results=true
model=nova-2
language=<language>
diarize=true|false
multichannel=true|false
keywords=<URL-limited keyword list>
```

Flow:

1. Obtain a temporary Deepgram token from the Superwhisper key endpoint or use a BYOK token.
2. Open the WebSocket with `Authorization: Token <token>`.
3. Send raw PCM signed 16-bit, 16 kHz audio frames.
4. Parse `channel.alternatives[].transcript`, word timing, speaker, confidence, and `is_final`.
5. End with:

   ```json
   {"type":"CloseStream"}
   ```

The app truncates keywords to stay below the request-URL limit.

wss://api.elevenlabs.io/v1/speech-to-text/realtime

Binary-confirmed session/configuration fields:

## What is fully replayable now

With valid credentials supplied by the user:

- ElevenLabs batch transcription through `api.superwhisper.com` — cache-confirmed and curl-verified
- S1 `/v1/c/run` while its inference JWT is unexpired
- Deepgram batch transcription with a temporary or BYOK token
- OpenAI/Groq transcription with BYOK credentials
- Superwhisper OpenAI-format cloud chat
- Direct OpenAI-compatible, Anthropic, Groq, Ollama, and LM Studio language-model requests

Partially documented but requiring one more disposable capture before robust automation:

- ElevenLabs and Deepgram temporary-token response schemas
- Full realtime WebSocket handshake/query values for every mode variant
- Modal `/generate` multipart field set
- License activation and email-verification bodies
- File delete/download bodies
- Statistics bulk root wrapper and server response
- Issue-report multipart body
- Any truncated internal `/apps/...` or `/users/...` routes

## Replay limitations

The main ElevenLabs batch path is now independently curl-verified. The templates still contain credential placeholders because the real values must not be stored in a deliverable.

Remaining limitations:

- The derivation of `X-Signature` is still unknown. A current value was sufficient for the verified replay.
- Authentication values may rotate or stop working when the license/device state changes.
- Apple curl cannot decode Brotli. Advertise `gzip, deflate`, use a Brotli-enabled curl, or decode the raw `br` response separately.
- The partially documented request families listed above still need disposable captures before robust automation.

## Bottom line

The current Default-mode transcription request is reconstructed and independently replayed down to its method, endpoint, complete header set, multipart part names, audio container/codec, and response schema. The only unresolved element needed for a caller that cannot reuse current credentials is how Superwhisper derives or provisions `X-Signature`; the successful curl test proves that a current authorized header set is sufficient for practical replay without reproducing that derivation.

## September 13, 2026: current S1-Voice protocol

Current cache inspection and live probes through Handy establish the following flow:

1. `GET https://api.superwhisper.com/v2/inference/regions` returns `regions` entries with `id` and `host`, and a `default` ID.
2. `POST https://api.superwhisper.com/v2/inference/key?region=<id>` sends `{}` as JSON with `X-ID`, `X-License`, `X-Signature`, and `X-Platform: macos`. The response contains `key`. This corrects the earlier inferred GET method and license-bearer authentication.
3. `POST <region-host>/generate` uses that key as a bearer token and multipart fields `audio`, `language`, `asr_prompt`, `enable_word_timestamps`, and `enable_audio_vocab`. The current regional host is separate from the older Cerebrium `/v1/c/run` route.
4. The JSON response contains top-level `text`. The regional public OpenAPI document at `https://us.aws.superwhisper.com/openapi.json` also lists `/generate`.

Two live requests through Handy accepted its existing 16 kHz mono PCM16 WAV encoding as `audio`, filename `recording.wav`, MIME type `audio/wav`. One used `language=en`; the other used `language=auto`. Both used an empty `asr_prompt`, `enable_word_timestamps=true`, and `enable_audio_vocab=false`. Both returned the generated phrase exactly:

> The purple bicycle is parked beside the library. This is a disposable speech recognition test.

The cached app request additionally supplied a `vocabulary` file named `vocab.bin` with `enable_audio_vocab=true`. Handy does not produce that file and instead sends plain vocabulary hints through `asr_prompt`.

## September 14, 2026: Ogg Opus upload verification

A disposable live request through Handy's Scribe provider accepted Ogg Opus produced by the in-process encoder at a target 32 kbps, with filename `recording.ogg` and MIME type `audio/ogg`. The transcript matched the generated input phrase. The request completed in approximately 0.94 seconds.

Independent FFmpeg decoding preserved all 89,358 input samples at 16 kHz, including Opus delay compensation and end trimming. A one-minute sample made by repeating generated speech encoded to 234,281 bytes, compared with 1,920,044 bytes for PCM16 WAV. Encoding took approximately 0.52 seconds in the local debug build. These measurements establish compatibility and compression for disposable speech, not accuracy parity across noisy recordings or other providers.


Disposable Ogg Opus requests to S1-Voice's regional `/generate` endpoint and OpenRouter's `/audio/transcriptions` endpoint using `fish-audio/transcribe-1` both returned HTTP 200 and the expected phrase, "The purple bicycle is parked beside the library." Both uploads used the same in-process encoder as Scribe.

OpenRouter's [transcription documentation](https://openrouter.ai/docs/guides/overview/multimodal/stt) recommends Opus for long recordings, while noting that accepted formats vary by provider. The [Codex ASR maintainer's format tests](https://github.com/Wangnov/codex-asr#audio-formats) list Ogg Opus with `audio/ogg` among successful uploads.
